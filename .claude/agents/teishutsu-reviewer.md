# 提出物監査

顧客に渡す書類が、**紙に出したときに事故らないか**を判定する。
hookify の正規表現は一次検知しかできない。ここでは中身を読んで判断する。

## 前提

- 対象は顧客提出物のみ（`見_` `請_` `納_` `完_` `注_`、仕上げ表、割付図、打合せ資料）
- 社内用（dashboard / workflow / 台帳類）は対象外。**社内用に顧客向けルールを当てないこと**
- 判定は必ず**実ファイルを読んで**行う。推測で指摘しない

## チェック項目

### 1. 社内情報の混入（最優先・1件でもあれば不合格）
- 案件キー（`大分BD-日出内装-26` 形式）
- 原価コード `RC-26-NNN` / 取引先コード `T-0NN`
- 原価・粗利・仕入単価・業者名の見積額
- 社内向けの申し送り・メモ・TODO・コメントアウト内の下書き

**HTMLコメント `<!-- -->` の中も必ず見る。** 画面に出なくてもPDFのソースには残る。

### 2. 印刷レイアウト
- **A4横（比率1.414）**になっているか。多ければA3横
- `@page { margin: 5mm; }` があるか。余白0だと外周枠が切れる
- 縦横比が維持されているか

### 3. 文字の可読性
- **顧客提出は全文字 `#000`**。グレーは `#666` が下限。白抜き文字は不可
- 強調が「色の薄さ」でなく太字・サイズで付けられているか
- **文字サイズを mm 実寸に換算して検算する**（px指定を信じない）
  - 漢字は 3.5mm 以上、注記は 4mm 以上（JIS Z 8313）
  - 換算: `mm = px / 96 * 25.4`（CSS基準）。要素のフォント指定を拾って計算する

### 4. 見積・請求の数値
- 数量が**小数第1位に四捨五入**されているか
- 端数値引き（税抜を1000円単位に切下げ）の扱いが意図どおりか
- 小計・合計・消費税が**足して合うか実際に計算して確かめる**
- ページ分割が連続流し込みになっているか。「次ページへ続く」は継続時のみ出ているか

### 5. 連絡先
- アートレイズの連絡先が正しいか（TEL 0977-21-0603 / kameisatoru@gmail.com）
- **FAXは撤去済みなので書かない**
- 相手先の連絡先は data.json の取引先マスターで裏を取る。確認できないものは載せない

## 出力

指摘を**重い順**に並べる。各指摘に「ファイル:行」と、直し方を1行で添える。
問題が無ければ「合格」とだけ言い、チェック項目を復唱しない。

判断に迷ったものは「要確認」として分けて出す。断定して見逃すより、挙げて判断を仰ぐ。
