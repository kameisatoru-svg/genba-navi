# 看板整合チェック

現場ナビは **data.json の「案件.チェック」が真実の源泉**で、
`dashboard.html`（ステータス看板）と `workflow.html`（動的描画）は
どちらも `check_template.js` の `CHECK_TEMPLATE` を見て描く。

この2つがズレると、**データは持っているのに画面に出ない**という
いちばん気づきにくい壊れ方をする。

## 実行

```bash
PYTHONUTF8=1 python tools/kanban_check.py
```

読み取り専用。何も書き換えない。ズレがあれば exit 1。

## 出力の読み方と対処

### [1] テンプレートに定義が無いステータス
**いちばん重い。** その案件は workflow.html でチェックリストを描画できない。

対処は2択：
- そのステータスを **`check_template.js` に定義する**（`CHECK_TEMPLATE['名前'] = {...}`）
- 既存ステータスと同じ扱いでよければ **エイリアスを張る**
  （例: `CHECK_TEMPLATE['調査中'] = CHECK_TEMPLATE['相談'];` が既にある）

`完了` `保守管理(継続)` `中止` `保留` のように**終わった案件・止まった案件**は、
チェックリストが不要なら「意図的に定義しない」判断もあり得る。
その場合は workflow.html 側が空を握っても壊れないかを確認し、
**判断の理由を check_template.js にコメントで残す**こと。次に見た人が同じ検討を繰り返さないように。

### [2] どのステータスのテンプレートにも無い項目ID
`check_template.js` から消した項目が data.json 側に残っている状態。
そのチェックは**もう永久に表示されない**。

- 項目を復活させるか、data.json 側から消すか決める
- data.json を触るときは**直接編集しない**（`artrays-data` MCP か `genba_progress.py` 経由）

※ 前のステータスで付けたチェックが残るのは**正常**なので、検査から除外してある。

### [3] 一度も使われていない項目ID
定義したが機能していない可能性。ステージ構成を変えたときの消し忘れが多い。
実際に使う予定が無ければ `check_template.js` から消す。

### [4] チェック未作成の案件
`チェック` が未作成なだけで、異常ではない。相談段階の案件が多いと自然に増える。
数が極端に増えていたら、`genba_progress.py event` が回っていない可能性を疑う。

## 走らせるタイミング

- `check_template.js` を編集した直後
- 案件のステータスを新しく増やしたとき
- 「ワークフローに何も出ない」と言われたとき
- 週次点検
