# 看板整合チェック

現場ナビは **data.json の「案件.チェック」が真実の源泉**で、
`dashboard.html`（ステータス看板）と `workflow.html`（動的描画）は
どちらも `check_template.js` の `CHECK_TEMPLATE` を見て描く。

この2つがズレると、**データは持っているのに画面に出ない**という
いちばん気づきにくい壊れ方をする。

## 実行

```bash
PYTHONUTF8=1 python tools/kanban_check.py
```

読み取り専用。何も書き換えない。ズレがあれば exit 1。

## 出力の読み方と対処

出力は **「要対応」と「設計判断」を分けて**出る。全部を直す必要はない。

### [1-A] 進行中なのにテンプレートが無い ← 本当の異常
`STATUS_ORDER`（相談→入金済み）に載っているステータスなのに定義が無い状態。
進行中の案件が手順を追えないので、**必ず定義する**。

### [1-B] 終端・停止ステータスでテンプレートが無い ← 判断するところ
`完了` `中止` `保留` `保守管理(継続)` など、パイプラインの外の状態。
**壊れてはいない。** 現在の挙動は:

- dashboard: 「ワークフローを開く」ボタンが出ない・進捗バーも出ない
- workflow.html を直接開くと『テンプレート未対応』と表示される

`description` だけの空テンプレートを定義しても、
**開くと『Phase 2 で実装予定』が出るだけ**（`完了(請求書作成済み)` が実例）。
`getCarryOverItems` は `STATUS_ORDER.indexOf(...) <= 0` で `[]` を返すため、
**STATUS_ORDER に足さない限り持ち越し項目も出ない**。

つまり選択肢は3つ:

| 選択 | 結果 |
|---|---|
| 定義しない | ボタンが出ない。終わった案件に手順は不要、という立場 |
| 空テンプレだけ定義 | ボタンは出るが中身は空。**期待して開いて空**になるので勧めない |
| 空テンプレ + STATUS_ORDER 追加 | 持ち越し（やり残し）が見える。終端の取りこぼし確認に使える |

判断したら、**理由を `check_template.js` にコメントで残すこと。** 次に見た人が同じ検討を繰り返す。

### [2] どのステータスにも無い項目IDを持つ案件
`check_template.js` から消した項目が data.json 側に残っている。永久に表示されない。
※ 前ステータスからの持ち越しは正常なので除外済み。

### [3] 一度も使われていない項目ID
定義したが機能していない可能性。ステージ構成を変えたときの消し忘れ。

### [4] チェック未作成の案件
異常ではない。極端に増えていたら `genba_progress.py event` が回っていない可能性。

### [5] 似たステータス名の併存
`完了` と `完了(請求書作成済み)` のように名前が割れていないか。
**片方だけテンプレートがある場合は、名前の揺れを疑う。**
統合するなら data.json 側のステータス値も揃える（`genba_progress.py status` で）。

### [6] 案件配列と中止案件配列の重複 ← 本当の異常
同じ案件が `案件` と `中止案件` の両方にある状態。集計が二重になる。
どちらを正とするか決めて片方から外す。**data.json は直接編集しない**
（`artrays-data` MCP か `genba_progress.py` 経由）。

## 走らせるタイミング

- `check_template.js` を編集した直後
- 案件のステータスを新しく増やしたとき
- 「ワークフローに何も出ない」と言われたとき
- 週次点検

exit 1 = [1-A] か [6] に該当あり。[1-B] [5] だけなら exit 0。
